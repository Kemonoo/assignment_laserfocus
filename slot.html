Process & methodology · Part 02

Industrial Sketchbook Slot Prototype

What I built

A playable, self-contained 2.5D slot machine with a draggable, clickable, and tappable lever, sequential reel stops, a credit system, win feedback, sound effects, and coin-drop effects. At the start of each pull, the game randomly selects one position from each virtual reel before the animation begins. The reels then animate to those positions, ensuring the spinning visuals always match the selected result.

Wins, rewards & probability

A win requires three matching symbols on the center payline. Payout multipliers are Seven 500×, Diamond 100×, Bell 40×, Cherry 16×, and Lemon 4×.

The game has three risk profiles. Each reel is a 20-position virtual strip, with common symbols occupying more positions than rare ones. Selecting one position from each reel produces 8,000 equally likely stop-position combinations, but only 125 visibly different three-symbol patterns. Changing the symbol distribution changes how many underlying positions produce each visible result.

Friendly 14.425% hit · 96.0% RTP Classic 11.125% hit · 91.2% RTP High Roller 9.700% hit · 92.0% RTP Win condition 3 matching center symbols

The math panel recalculates when the mode changes. The code counts how many positions each symbol occupies on every reel, groups the equivalent visible results, and uses those exact counts to calculate hit rate and theoretical RTP rather than estimating them through random simulation.

How it works

  • Lightweight 2.5D engine: Instead of building a heavy 3D WebGL environment, the cabinet, reels, lever, symbols, and coins are separate image layers animated with HTML, CSS, and vanilla JavaScript.
  • Visual anticipation: The engine selects the three target stops first, then lands the reels one by one with a slightly longer delay on the final reel to build suspense.
  • Source and delivery: The complete prototype and source are available in the linked GitHub repository and run as a normal web page.

AI workflow & design decisions

The process was a back-and-forth collaboration between different AI tools, using each for its strongest role and adapting the workflow when token or implementation limits appeared.

  • Gemini — planning & text: Used for high-level brainstorming, structuring the assignment approach, and drafting written content.
  • ChatGPT — code, assets & logic: Built the initial functional game and helped develop the mechanical sketchbook direction with DALL·E concepts after the first visual version felt too generic.
  • The 2.5D workaround: When Claude Design struggled to convert one complete sketch directly into clean interactive HTML, ChatGPT generated separate PNG layers for the cabinet, reels, lever, and coins, then assembled them so each part could move independently.
  • Claude Design — UI & website layout: Polished the assembled machine, corrected visual imperfections, and placed it inside a responsive sketchbook-style presentation.
  • Final deployment: ChatGPT / Codex prepared the GitHub updates, verified the live-page behavior, and aligned the presentation styling across both parts of the assignment.

I directed the process by choosing the art direction, selecting references, rejecting weak iterations, and giving detailed feedback on the machine's perspective, lever movement, reel cropping, and overall clarity.
